# BRI1 V3-R1 IMPLEMENTATION AUDIT 01
## Post-execution audit of `076e824` (V3-R1)

**Finding: LOAD-BEARING IMPLEMENTATION DEFECT.** `V3-R1-ILLUSTRATION-PASS` is **NOT RATIFIED**.

## 1. The tensor-grid broadcasting defect

The intended computation was tensor quadrature over all phase-space pairs `(x_i, p_j)`. The implementation in `publication_verification/v3_r1/v3_r1.py` instead calls `duffing_integral(xs, ps, ...)` and `integrate_eps(xs, ps, ...)` with `xs` and `ps` both one-dimensional arrays of the same length. NumPy therefore evolves **pairwise states `(x_i, p_i)`** and returns a one-dimensional trajectory array. That 1-D result was then multiplied by the 2-D Gibbs weight matrix `Wn`, where broadcasting silently produced an invalid expectation — effectively integrating each p_i only against its paired x_i, with each pair's Gibbs weight misplaced.

## 2. The P0 stationarity violation that exposed it

Under the unforced Duffing Hamiltonian with the frozen Gibbs preparation, ρ ∝ exp[−p²/2 − x²/2 − x⁴/4] is invariant under the flow. Therefore, for the intended ensemble:

- E[x(t)] = 0 for all t;
- Var[x(t)] = E[x²] = **constant** (equal to the t=0 Gibbs value) for all t;
- κ₃[x(t)] = 0 for all t.

V3-R1 instead reported P0 variances changing with time:

| t | reported Var(P0) |
|---|---|
| 0.25 | 1.23475 |
| 0.5 | 0.96005 |
| 0.75 | 0.56231 |
| 1.0 | 0.34585 |

This is impossible for the intended Gibbs ensemble (the correct value is constant ≈ 0.46). The pairwise-evolution defect (p_i evolving under the flow generated by x_i, rather than every p_j paired with every x_i) destroys the product structure of the ensemble, producing a spurious time-dependent "variance." The P0 control did exactly its job: it exposed the defect.

**This is a numerical implementation failure, not a theorem failure.** V1 and V2 are untouched.
